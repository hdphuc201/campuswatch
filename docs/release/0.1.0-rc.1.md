# CampusWatch 0.1.0-rc.1 — pilot release candidate

Release candidate for a 5–20 student pilot (implementation plan, P8). Software complete;
external gates are listed at the end.

## For students

- Chrome extension (Manifest V3) with CampusWatch account sign-in, consent, and connection to
  the CITD Portal session you already have in Chrome.
- Reads grades and GPA, tuition (summary and per-course), timetable, exam schedule, and
  Dashboard notices about every 30 minutes while Chrome runs (± 3 minutes jitter).
- Shows "Connected" only after the Portal was actually read; clear states for Portal login
  needed, Portal or network problems, and layout changes.
- Recent changes in the popup; Chrome notifications and optional Telegram messages, summary by
  default (no scores or amounts), detailed on request; quiet hours.
- Pause, resume, disconnect, data export, data deletion, and account deletion.
- Portal reading is labeled beta until verified against the live Portal.

## Platform

- API (NestJS/Fastify), worker (NestJS/BullMQ), PostgreSQL 16, Redis 7.
- Idempotent snapshot ingest with field-level change history; one notification per real change.
- Telegram linking with one-time codes, webhook secret, and encrypted chat ids.
- Rate limits, redacted JSON logs, consistent error codes, security headers, retention jobs,
  aggregate operations metrics.
- Container images for API, worker, and migrations; staging compose stack with automatic HTTPS;
  configuration preflight (`check-config`); verified extension packaging.

## Permissions (extension)

`storage`, `alarms`, `scripting`, `notifications`; host access to `https://portal.citd.edu.vn/*`
and the CampusWatch API only. No `cookies`, no access to other sites.

## Upgrade notes

- Database migrations `0000`–`0003`; run automatically by the `migrate` image.
- `POST /auth/register` returns 202 and never reveals whether an email exists; clients sign in
  afterwards.

## Known limitations and external gates

- **Live Portal verification:** CITD page paths and column names come from a synthetic baseline;
  a student must verify them read-only with their own account before the pilot.
- **Telegram:** needs a real bot token and a registered HTTPS webhook.
- **Hosting:** staging/production host, DNS, TLS, and backups are not provisioned by this
  repository.
- **Email:** no email verification or password recovery yet (needs an email provider).
- **Distribution:** pilot uses "Load unpacked"; Chrome Web Store publication is separate.
- Monitoring happens only while Chrome is running (by design, ADR-0001).
